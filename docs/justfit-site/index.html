How it fits

Three mechanisms.
One memory budget.

Quantizing the KV cache is only the first step — usable context is set by every allocation that overlaps it: weights, resident pages, attention operands, prefill workspace, speculative state, component lifetimes. JustFit treats their overlap as the actual problem.

01KVEXEC

Compact in storage.
Bounded in execution.

Page-addressed 4-bit KV, page-native decode, and direct-inverse reconstruction of only the current layer's floating-point attention operands — never a second full-precision copy.

02PHASESWAP

Components follow
live owners.

The output head, vision tower, and speculative drafter attach only when a request actually needs them, and detach at scheduler-selected safe boundaries — not when you remember to free them.

03STATETRANS

Change execution.
Keep the context.

A request can move speculative → batched → speculative decoding without migrating its surviving KV. Completed and cancelled rows return their pages for immediate reuse.

What JustFit doesn't claim

Boundary, not default.

The headline numbers are real, and they are also the ceiling — not what you should run every day. Stated up front so you don't have to find out the hard way.

  • The fully cold 240K+16K run takes about 114 minutes. It's a full-execution memory stress test with repetitive text and EOS suppression — not a daily preset. The Quick Start ships a 64K-input + 8K-output profile instead.
  • 320K is aggregate across two requests, not one 320K conversation. The strongest single-request shape is the native 256K window (240K input + 16K output).
  • 29/30 on AIME 2026 is an integrated reasoning check, not a 256K-context comprehension test. The two KV formats compared differ in storage path and recovery, not just bit width.
  • Image admission beside a live text request is one measured 196,608-input trial, not a reliability guarantee — the boundary case sampled only 20 MiB below the guard.
